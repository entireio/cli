  Important Discoveries

  PR #1045 was about DB credential gaps after Betterleaks. It did
  not broadly solve transcript command shapes.

  Betterleaks already catches normal OpenSSH private-key blocks
  like:

  -----BEGIN OPENSSH PRIVATE KEY-----
  ...
  -----END OPENSSH PRIVATE KEY-----

  The more relevant missed case became the transcript command
  shape where a low/moderate entropy literal is piped into a
  secret-setting command. Entropy alone does not reliably catch
  values like correct-horse-client or similar human-ish secrets.

  GITHUB_CLIENT_SECRET is a real credential and worth redacting.

  CLIENT_ID, Application ID, and GOOGLE_ADSENSE_ACCOUNT=pub-...
  are more like identifiers/accounts and should not automatically
  be redacted unless the value itself independently looks secret-
  like.
