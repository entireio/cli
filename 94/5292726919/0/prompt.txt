### 1. MEDIUM — `formatReviewSessionLine` cannot distinguish "no prompt yet" from "I/O error on prompt.txt"
**Location:** `/Users/peytonmontei/Documents/entire/devenv/entireio/cli/.worktrees/review-fix-2/cmd/entire/cli/review_context.go:244-253`

```go
raw, err := os.ReadFile(promptPath)
if err != nil {
    return ""
}
```

The PR description claims "Sessions whose prompt.txt is missing or empty are skipped silently." That phrasing implies `os.IsNotExist(err)` and "empty content" — two well-defined, expected, optional-input cases. But the code's actual behaviour is "any `os.ReadFile` error, including permission-denied, EIO, EACCES, ELOOP (symlink loops), and ENAMETOOLONG, is silently swallowed and the session disappears from the context block." StateStore.List already swallows corrupt-JSON state files at `session/state.go:548`, so the silent-skip chain runs two layers deep with no operator trace.

**Hidden errors:**
- Permission-denied on `.entire/metadata/&lt;session&gt;/prompt.txt` (umask / chmod drift after `entire enable`)
- `EACCES` on parent directory traversal
- `EIO` (filesystem corruption)
- A genuinely zero-byte `prompt.txt` (which IS a real bug — the lifecycle hook failed to append for every turn this session, but the file got created)

**User impact:** A user who explicitly knows they have an active session in this worktree will see no "In-progress session context" block at all and have no way to know why. There's no debug line to grep for.

**Recommendation:** Split the cases. `os.IsNotExist(err)` and empty content → silent skip (these ARE expected for a fresh session that hasn't taken a turn yet). Any other I/O error → `logging.Debug(ctx, "review session context: read prompt", slog.String("session_id", st.SessionID), slog.String("error", err.Error()))` then skip. Pass `ctx` into `formatReviewSessionLine` to enable this.

```go
func formatReviewSessionLine(ctx context.Context, worktreeRoot string, st *session.State) string {
    promptPath := filepath.Join(worktreeRoot, paths.SessionMetadataDirFromSessionID(st.SessionID), paths.PromptFileName)
    raw, err := os.ReadFile(promptPath)
    switch {
    case err == nil:
        // fall through
    case errors.Is(err, fs.ErrNotExist):
        return "" // expected: session hasn't completed a turn yet
    default:
        logging.Debug(ctx, "review session context: read prompt failed",
            slog.String("session_id", st.SessionID),
            slog.String("path", promptPath),
            slog.String("error", err.Error()))
        return ""
    }
    // ...
}
```

### 2. MEDIUM — `canonicalisePath` silently swallows non-ENOENT errors from `EvalSymlinks`
**Location:** `/Users/peytonmontei/Documents/entire/devenv/entireio/cli/.worktrees/review-fix-2/cmd/entire/cli/review_context.go:232-240`

```go
if resolved, err := filepath.EvalSymlinks(p); err == nil {
    return resolved
}
return p
```

The doc comment correctly notes the ENOENT case ("path doesn't exist yet"). But `EvalSymlinks` also returns errors for symlink loops, EACCES on intermediate components, and ENAMETOOLONG — none of which the function distinguishes from ENOENT. When the comparison is symmetric (both sides fall back to raw), this is usually harmless. But it can produce subtle false negatives: if the on-disk state file stores a `/private/var/...` form AND `EvalSymlinks` on the caller's worktree path fails with EACCES while the state path resolves cleanly, the two sides compare unequal and the session is silently dropped.

**Hidden errors:** EACCES on a parent, symlink loop, ENAMETOOLONG.

**Recommendation:** Either swap to debug-logged switch (similar to finding 1), or document explicitly that the fallback chain is "any error → raw path comparison; comparison is symmetric so worst case both sides degrade together." The current `Falls back to p itself when EvalSymlinks fails (e.g., the path doesn't exist yet)` comment misleads — `(e.g., ...)` reads as "this is the only case" when in fact several other error classes also hit the fallback.

## Critical Gaps (8-10)

### 1. The three-dot diff fix has no regression test — rating 8

`/Users/peytonmontei/Documents/entire/devenv/entireio/cli/.worktrees/review-fix-2/cmd/entire/cli/review/scope.go:217-234` documents that `countFilesChanged` uses three-dot syntax specifically to avoid over-counting upstream changes as "reversed deltas". ### 2. No test for `detectScopeBaseRef` fallback chain ordering — rating 7-8
