## Critical Issues

### 1. SaveStep comment overstates the guarantee — and hides a latent bug

**Location**: `/Users/peytonmontei/Documents/entire/devenv/entireio/cli/.worktrees/pr-review/cmd/entire/cli/strategy/manual_commit_git.go:125-140`

**Issue**: The comment claims:

&gt; "accumulateTokenUsage already replaces (rather than adds) the SubagentTokens field for that reason, so state.TokenUsage ends up correctly holding the latest cumulative total."

Replacement is **conditional**: `accumulateTokenUsage` only replaces when `incoming.SubagentTokens != nil` (manual_commit_git.go:366-368). And `SubagentTokens` can legitimately arrive nil mid-session even after a subagent was previously counted: `CalculateTotalTokenUsage` only sets it when `subagentUsage.APICallCount &gt; 0` (claudecode/transcript.go:438, factoryaidroid/transcript.go:404), and each per-subagent read `continue`s on error — the code's own comment says the transcript "may have been cleaned up" (claudecode/transcript.go:429-430).

The consequence the comment glosses over: the baseline subtraction at lines 137-140 runs on **every** step with non-nil `step.TokenUsage`, but is only idempotent when replacement actually happened that step. Trace the nil case:

- Step N (snapshot present): `CheckpointTokenUsage.SubagentTokens` = fresh cumulative snapshot → minus baseline → correct delta.
- Step N+1 (`SubagentTokens == nil`): accumulate leaves the field at the **already-rescoped delta**; the SaveStep block then subtracts the baseline **again** → double subtraction, silently clamped to zero by `clampSubtract`.

The invariant the subtraction depends on ("this field is a fresh cumulative snapshot whenever this line runs") is exactly what the comment should state — instead it asserts the conclusion ("ends up correctly") without the precondition. A future maintainer reading this comment will believe the rescoping is unconditionally safe. Note also that `clampSubtract`'s doc (`types/token_usage.go:72-73` — "so a stale or racy baseline never produces a negative delta") inadvertently documents the mechanism that masks this bug.

**Suggestion**: Either fix the code so the comment becomes true (e.g., compute the delta from the fresh snapshot — `SubtractTokenUsage(step.TokenUsage.SubagentTokens, state.SubagentTokensBaseline)` — guarded by `step.TokenUsage.SubagentTokens != nil`, instead of subtracting from possibly-already-rescoped state), or amend the comment to state the precondition honestly: "This subtraction assumes accumulateTokenUsage replaced SubagentTokens with a fresh cumulative snapshot this step; when step.TokenUsage.SubagentTokens is nil (subagent transcripts unreadable/cleaned up), the field still holds the prior step's delta and re-subtracting under-counts (clamped at zero)." Given this is a token-accuracy PR, the code fix is the better outcome.

Minor secondary inaccuracy in the same block: "state.TokenUsage ends up correctly holding the latest cumulative total" — when incoming is nil it holds the last *known* snapshot, which is the right behavior, but "already replaces" is stated as unconditional when it isn't.

## What this PR does well

## Finding 1 — Subagent transcript read errors are 100% silent, and this PR makes that silence load-bearing

**Severity: HIGH** (loop pattern pre-existing; materially amplified by this PR)
**Locations:**
- `cmd/entire/cli/agent/claudecode/transcript.go:427-431` (token loop: `CalculateTokenUsageFromFile` error → bare `continue`)
- `cmd/entire/cli/agent/claudecode/transcript.go:488-492` (files loop: `ParseFromFileAtLine` error → bare `continue`)
- `cmd/entire/cli/agent/factoryaidroid/transcript.go:394-397` and `:447-450` (same pattern, `ParseDroidTranscript`)

**Hidden errors.** The only errors these calls can return are file-level (`cmd/entire/cli/transcript/parse.go:57-61`, `factoryaidroid/transcript.go:41-48`): `ENOENT` (expected — subagent not started yet), but also `EACCES`, `EISDIR`, symlink loops, and mid-read I/O errors (all unexpected). All are collapsed into one silent `continue`. There is **no logging call of any kind** — not even `logging.Debug` — despite the claudecode package already importing and using `logging` elsewhere (`discovery.go:39`, `lifecycle.go:211`). A subagent's tokens and modified files simply vanish, and six months from now nobody debugging "checkpoint missing a file the subagent wrote" will find a single log line.

**Why the PR amplifies it — two ways:**

1. **More agents whose files can be gone.** Discovery now scans the full transcript (`transcript.go:406-410`), so on long-running or resumed sessions it finds every subagent since session start — including ones whose `agent-*.jsonl` files Claude Code has since pruned (its `cleanupPeriodDays` transcript cleanup) or that predate a `~/.claude` relocation. Pre-PR, slice-scoped discovery naturally aged those agents out; post-PR each of them is a fresh silent-skip on every single call.

2. **The silence now violates a correctness invariant.** The new replace-semantics (`manual_commit_git.go:367`) plus baseline subtraction (`manual_commit_git.go:137-140`) implicitly require the cumulative snapshot to be **monotonically non-decreasing**. A subagent file that becomes unreadable makes the snapshot silently *shrink*. Consequences, all invisible: `state.TokenUsage.SubagentTokens` (shown by `entire session tokens`, `sessions.go:626-632`) silently drops backwards on the next replace; and `clampSubtract` flattens the now-negative checkpoint delta to 0. Pre-PR the `continue` merely undercounted one turn. Post-PR it corrupts the running total *and* the delta math. The silent skip went from "lossy" to "actively poisoning the new arithmetic."

**Recommendation.** Distinguish `os.IsNotExist` (legitimately expected mid-turn) from everything else, and debug-log both, warn-log the unexpected class:

```go
agentUsage, err := CalculateTokenUsageFromFile(agentPath, 0)
if err != nil {
    if os.IsNotExist(err) {
        logging.Debug(ctx, "subagent transcript not yet present", slog.String("path", agentPath))
    } else {
        logging.Warn(ctx, "subagent transcript unreadable; its tokens will be missing from this checkpoint",
            slog.String("path", agentPath), slog.String("error", err.Error()))
    }
    continue
}
```

The interface method lacks a `ctx` parameter; `context.Background()` is acceptable for logging, or plumb `ctx` through when the `Agent` interface is next touched.

## Finding 2 — Double-subtraction of the baseline when a step arrives with nil `SubagentTokens`, silently clamped to zero

**Severity: HIGH — introduced by this PR**
**Location:** `cmd/entire/cli/strategy/manual_commit_git.go:137-140`, masked by `cmd/entire/cli/agent/types/token_usage.go:74-79`

The rescope runs on **every** `SaveStep` where `step.TokenUsage != nil`, but `accumulateTokenUsage` only *replaces* `SubagentTokens` when the incoming snapshot is non-nil (`manual_commit_git.go:366-368`). Trace two steps in one checkpoint window, baseline `B` from the last condensation:

- Step 1: incoming snapshot `S` → accumulate sets `CTU.SubagentTokens = S` → line 138 rescopes to `S − B`. Correct.
- Step 2: incoming `SubagentTokens == nil` → accumulate **retains** the already-rescoped `S − B` → line 138 subtracts `B` **again** → `clamp((S − B) − B)`.

If `S &lt; 2B` (typical shortly after a condensation) the delta silently becomes **0**; otherwise it's an arbitrary undercount. Either way `clampSubtract` guarantees the corruption looks like a valid number.

**Is nil-after-non-nil reachable?** Yes:
- All subagent files unreadable this turn (Finding 1's cleanup/permission scenario) → `subagentUsage.APICallCount == 0` → `SubagentTokens` never set (`claudecode/transcript.go:438-440`).
- Race: a just-spawned subagent's transcript exists but contains no assistant/usage lines yet at stop-hook time → `APICallCount == 0` → nil, while a previous step in the same window already carried a snapshot.

**On the clamp itself.** `clampSubtract` is documented as protection against "a stale or racy baseline" — but it is equally the only thing standing between this exact class of defect and a visible negative number. Flooring at zero for display is defensible; doing it with **zero telemetry** means the one signal that would have exposed this double-subtraction (a negative delta) is destroyed at the source. `types` has no `ctx`/logging access, so detect it at the call site, where strategy has both:

```go
if step.TokenUsage.SubagentTokens != nil &amp;&amp; state.CheckpointTokenUsage != nil {
    if state.SubagentTokensBaseline != nil &amp;&amp;
        state.CheckpointTokenUsage.SubagentTokens.InputTokens &lt; state.SubagentTokensBaseline.InputTokens {
        logging.Warn(ctx, "subagent snapshot below baseline; delta clamped",
            slog.String("session_id", sessionID), ...)
    }
    state.CheckpointTokenUsage.SubagentTokens = types.SubtractTokenUsage(
        state.CheckpointTokenUsage.SubagentTokens, state.SubagentTokensBaseline)
}
```

Note the fix is the added `step.TokenUsage.SubagentTokens != nil` condition: only rescope when accumulate actually replaced the snapshot. A structurally safer alternative: keep the **raw cumulative** in `CheckpointTokenUsage.SubagentTokens` and subtract the baseline exactly once, at condensation/report time — that makes the operation idempotent by construction instead of by careful step ordering.

The new test (`cmd/entire/cli/strategy/subagent_token_dedup_test.go:515+`) never exercises a nil-`SubagentTokens` step after a non-nil one, so this path is untested.

## Hunt 2 — JSONL walker fallback/skip branches

**HIGH (pre-existing, inherited by the new layer): `applyJSONReplacements` silently no-ops on raw-encoding mismatch — secret reaches output with nil error and no log.** redact.go:703-727 / 733-770. The walker redacts the *decoded* leaf, then substitutes `jsonEncodeString(original)` into the raw text via string match. When the raw file encodes the leaf differently than Go's encoder — `\/` (solidus escape), `\u00e9` (Python `json.dumps` `ensure_ascii=True`), `\u003c` (Go HTML escaping) — the match fails, `strings.ReplaceAll`/`replaceKeyedJSONValue` find nothing, and the function returns success with the secret intact. Verified:

```
{"text":"a\/b then sb_secret_AbC…"}        → leaked, nil error
{"text": "caf\u00e9 \u003ckey\u003e sb_secret_AbC…"} → leaked, nil error
```

Because the line parsed as valid JSON, the malformed-line fallback (`redactor(line)`, redact.go:602-604 — which *would* catch it) never runs. This is exactly the failure class this PR exists to close (low-entropy secret, no other layer as backstop), just one branch over. Recommend a follow-up: count landed replacements and fall back to whole-line `String()` (or at least `logging.Warn`) when a collected replacement finds zero occurrences. Not introduced by this PR, but the PR's threat model makes it worth filing.

**MEDIUM (pre-existing, deliberate): skip lists pass secrets through unexamined.** Verified leaks via `JSONLContent`:
- `shouldSkipJSONLField` (redact.go:831-850): a Supabase secret as the value of `signature`, any `*id`/`*ids` key (e.g. `session_id`), or `path`/`cwd`/`dir`/… passes through raw — including entire *subtrees* under those keys, since `walk` is never called on the child.
- `shouldSkipJSONLObject` (redact.go:853-856): `{"type":"image","note":"sb_secret_…"}` — *all sibling fields* of an image-typed object are skipped, not just the base64 payload.
- Keys are never redacted (redact.go:794-823 walks values only): `{"sb_secret_…":"value"}` leaks the key.

These are documented design trade-offs (ID-corruption avoidance), but they are silent — nothing records "N leaves skipped." Pre-existing; the PR neither introduces nor worsens them, but its docs now promise deterministic prefix redaction "regardless of … surrounding context," which these branches qualify.

Non-string leaves (numbers/bools) are a non-issue — the provider charset can't survive JSON number/bool syntax. The malformed-line fallback correctly applies the full `String()` pipeline (covered by the PR's tests). No size caps exist in the walker.
